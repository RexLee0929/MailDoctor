# MailDoctor 1.0.0

自建邮箱的配置体检工具：给定域名，逐项验证收信、发信认证、服务发现、自动配置端点、端口与证书、账号登录，并给出可照着补的修正清单。

## Highlights

- **六组体检**：收信与投递、发信认证、服务发现、自动配置端点、端口与证书、账号实测。
- **不只看记录在不在**：实际抓取并解析 autoconfig、Autodiscover、mobileconfig、MTA-STS 的内容，校验 XML 命名空间。
- **按客户端真实回退顺序判定**：Thunderbird、BlueMail、Spark、Apple Mail、Outlook、K-9/FairEmail，并保留「凭 `mail.<域名>` 惯例配置」的兜底结论。
- **端口探测避开本机代理**：用自解析 IP 直连并显式指定 SNI，不依赖系统解析。
- **零依赖**：只用 Python 标准库，`python run.py` 即可运行；也可以直接拉取 GHCR 镜像，用 Docker 运行。

## 获取方式

两种方式二选一，功能完全相同。

**镜像运行（Docker）**

```bash
docker pull ghcr.io/rexlee0929/maildoctor:1.0.0
docker run -d --name maildoctor -p 127.0.0.1:8787:8787 ghcr.io/rexlee0929/maildoctor:1.0.0
```

打开 `http://127.0.0.1:8787`。镜像只构建 `linux/amd64`；若镜像为私有，先 `docker login ghcr.io`。仓库里的 `docker-compose.yml` 已填好镜像名和加固参数，也可以直接 `docker compose up -d`。

**源码运行**

```bash
git clone https://github.com/RexLee0929/MailDoctor.git
cd MailDoctor
python run.py
```

不需要 `pip install`，也不需要虚拟环境。

完整变更见仓库根目录的 `CHANGELOG.md`，使用说明见 `README.md`。

## 系统要求

Docker 方式只需要 Docker；要用仓库里的 `docker-compose.yml`，需要 Compose v2（`docker compose` 命令）。源码方式需要 Python 3.9 或更新版本，不需要第三方包。镜像仅构建 `linux/amd64`。扫描需要运行环境能访问 DNS 与目标的 25 / 143 / 465 / 587 / 993 / 995 端口。

## 已知限制

- 不能验证 DKIM 是否真的在签名，只能验证公钥记录存在且长度达标；验证签名要发一封真信看头部。
- 客户端矩阵覆盖 Thunderbird、BlueMail、Spark、Apple Mail、Outlook、K-9/FairEmail，未覆盖 Samsung Mail、eM Client 等专有实现。
- 不做投递实测（不发信到 Gmail / Outlook 观察落点），这一步仍然需要人工完成。
- 公网模式 `--public` 只提供限流与内网拦截，不是认证；对外暴露必须自行加访问控制。
- 扫描结果受运行环境影响：本机代理、防火墙、DNS 出口都可能改变结论，换一个网络复扫有助于区分。
