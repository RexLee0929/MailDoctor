# MailDoctor 1.0.0

首个版本。自建邮箱的配置体检工具：给定域名，逐项验证收信、发信认证、服务发现、自动配置端点、端口与证书、账号登录，并给出可照着补的修正清单。

起因是 Poste.io 免费版不带官方诊断，DNS 少一条记录、Autodiscover 的 XML 命名空间写错一个字母、证书没覆盖 `autodiscover.` 子域，都表现为「客户端提示密码错误」或「发给 Gmail 直接进垃圾箱」，很难从服务器日志反推。

## 获取方式

Docker 镜像（AMD64）：

```bash
docker pull ghcr.io/<owner>/maildoctor:latest
```

或从源码运行，零依赖，不需要 `pip install`：

```bash
python run.py            # http://127.0.0.1:8787
python run.py --cli example.com
```

## 这个版本包含

- 六个分组的体检项：收信与投递、发信认证、服务发现、自动配置端点、端口与证书、账号实测
- DNS 双通道解析（DoH 优先，原生 UDP 53 兜底），不依赖本机解析器
- 实际抓取并解析 autoconfig / Autodiscover / mobileconfig / MTA-STS 的**内容**，而不只看记录在不在
- 按各客户端真实的回退顺序判定自动配置能力，并保留「凭 `mail.<域名>` 惯例可配置」的兜底结论
- 端口探测使用自解析 IP 直连 + 显式 SNI，避开本机代理 fake-ip 造成的「所有端口都开着」
- IMAP / SMTP 登录实测，只做握手，不发送任何邮件

## 已知限制

- 不能验证 DKIM 是否真的在签名，只能验证公钥记录存在且长度达标。验证签名要发一封真信看头部。
- 客户端矩阵覆盖 Thunderbird / BlueMail / Apple Mail / Outlook / 惯例识别，未覆盖 Samsung Mail、eM Client 等专有实现。
- 不做投递实测（不发信到 Gmail / Outlook 观察落点）。这一步仍然需要人工做。
- 公网模式 `--public` 只提供限流与内网拦截，**不是认证**；对外暴露必须自行加访问控制。
