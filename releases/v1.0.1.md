# MailDoctor 1.0.1

自建邮箱的配置体检工具：给定域名，逐项验证收信、发信认证、服务发现、自动配置端点、端口与证书、账号登录，并给出可照着补的修正清单。这是 1.0.0 之后的维护版本，主要修容器部署。

## 本次改动

**日志落盘交给程序自己管**

- `run.py` 新增 `--log-file`：输出同时写入指定文件，超过 10 MB 轮转一份（`maildoctor.log` → `maildoctor.log.1`）。
- 起因是 Docker 的 `json-file` 驱动由守护进程写 `/var/lib/docker`，compose 无法把它映射到宿主机目录。想在宿主机上直接看日志，只能让程序自己写。

**compose 修正**

- 宿主机端口 `8787` → `8006`，容器内仍监听 8787；换个端口是为了和宿主机上已有的服务错开，绑定的仍是回环地址，由反代对外。
- `TZ` 原先写成列表形式，Compose v2 会忽略，已改为标准键值对。
- 删掉无效的 `com.docker.network.enable_ipv6` 驱动选项（只对内置 bridge 生效），IPv6 由网络定义里的 `enable_ipv6: true` 开启。
- 自定义网桥显式声明：固定桥名 `br-maildoctor`、固定子网 `172.26.0.0/16` 与 `fd00:dead:beef::/48`，按接口名或网段放行时不用猜随机串。
- 容器自身日志轮转从 `10m × 3` 收紧为 `5m × 2`，因为应用已经自己落盘，这份只是兜底。

## 获取方式

**镜像运行（Docker）**

```bash
docker pull ghcr.io/rexlee0929/maildoctor:1.0.1
docker run -d --name maildoctor -p 127.0.0.1:8787:8787 ghcr.io/rexlee0929/maildoctor:1.0.1
```

打开 `http://127.0.0.1:8787`。镜像只构建 `linux/amd64`；若镜像为私有，先 `docker login ghcr.io`。

**compose 部署**

仓库里的 `docker-compose.yml` 已填好镜像名与加固参数，宿主机端口是 `8006`：

```bash
mkdir -p logs && sudo chown 10001:10001 logs   # 容器以非 root 运行，写不进去就没有日志
docker compose up -d
```

**源码运行**

```bash
git clone https://github.com/RexLee0929/MailDoctor.git
cd MailDoctor
python run.py
```

不需要 `pip install`，也不需要虚拟环境。

完整变更见 `CHANGELOG.md`，使用说明见 `README.md`。

## 系统要求

Docker 方式只需要 Docker；用 `docker-compose.yml` 需要 Compose v2。源码方式需要 Python 3.9 或更新版本，无第三方包。镜像仅构建 `linux/amd64`。扫描需要运行环境能访问 DNS 与目标的 25 / 143 / 465 / 587 / 993 / 995 端口。

## 已知限制

- 不能验证 DKIM 是否真的在签名，只能验证公钥记录存在且长度达标；验证签名要发一封真信看头部。
- 客户端矩阵覆盖 Thunderbird、BlueMail、Spark、Apple Mail、Outlook、K-9/FairEmail，未覆盖 Samsung Mail、eM Client 等专有实现。
- 不做投递实测（不发信到 Gmail / Outlook 观察落点），这一步仍然需要人工完成。
- 公网模式 `--public` 只提供限流与内网拦截，不是认证；对外暴露必须自行加访问控制。
- 扫描结果受运行环境影响：本机代理、防火墙、DNS 出口都可能改变结论，换一个网络复扫有助于区分。
